# 0.1.4：HE★ 批量编码超时修复

日期：2026-11-02。用户确认已勾选兼容，错误仍为“图片处理超过 60 秒”；与 0.1.3 的默认开关问题不同。

## 处理

HE/HE★ 兼容解码已经得到相机 JPEG，但旧“原格式”路径仍转换为约 2000 万像素 PNG；有损档还会尝试多个完整尺寸颜色量化候选。这条路径可能超过单图 60 秒预算。此前只验证原格式保真和显式 JPG，没有覆盖原格式有损档，本轮补齐。

- 兼容 NEF 的原格式输出改为 JPG。保真档在方向无需额外变换时，直接提取经过验证的内嵌 JPEG，不重复编码；其余档位按对应 JPG 质量编码。
- 保留 RAW-only 方向变换的正确性：如果仅靠 JPEG 自身方向标记无法满足显示方向，就从已经转正的 bitmap 编码。
- 将非 PNG 输入转换为不小于 800 万像素的 PNG 时，使用浏览器快速无损 PNG 编码，跳过 WASM 优化及颜色量化候选搜索；表格明确说明策略和 JPG/WebP 体积建议。
- 原生 PNG 输入继续原有优化路径，避免改变其保真/元数据行为。
- 不提高单图 60 秒超时，不缩小照片尺寸；保留 ZIP 取消和错误保护、结果变大保留原件、默认 HE★ 兼容。
- 内嵌 JPEG 仍不是完整 RAW 解码。

## 验证与交付

754 项单元测试通过，Web 类型检查、生产构建通过；Windows 免安装构建包含独立类型检查。

scripts/desktop-batch-fix-test.mjs 用用户 D:\\test 的两张 HE★ NEF 及 HEIC：
1. 原格式保真。
2. 显式 JPG、均衡。
3. 原格式轻度、均衡、强力三档。
4. 显式 PNG、强力。

每轮断言无失败条目；原格式 HEIC 逐字节保留；JPG 解包后由独立 nativeImage 解码确认两张 NEF 成品均 5568×3712。超时预算保持 60 秒，PNG 强力路径验证快速无损策略说明。

交付：release/DevKit-Images-0.1.4-win-x64-portable.zip。ZIP 校验和、app.asar 与实测应用一致性另验。关闭旧版，解压全部内容后运行新目录的 DevKitImages.exe。
