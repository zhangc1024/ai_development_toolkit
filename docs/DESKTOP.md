# 后续 Windows 桌面端规划

当前只交付网页工程，不含 Electron/Tauri 依赖、原生权限、安装包或自动更新。这里记录可复用设计，避免下一阶段推倒重做。

## 1. 可直接复用的内容

- Vue 页面、菜单注册、样式和 CodeMirror 编辑器。
- core.ts 的 JSON 处理逻辑及同一套核心测试。
- Web Worker 的本地计算模型，需在桌面容器中验证加载路径。
- 输入仅在内存的默认行为。
- Hash 地址与相对资源路径，减少部署路径耦合。

## 2. 两类容器的取舍

| 方向 | 开发影响 | 应重点验证 |
| --- | --- | --- |
| Electron | 主要使用 JS/TS；独立 Chromium 运行时通常带来较大安装体积 | preload/IPC 边界、禁用渲染页直接 Node 权限、安装体积 |
| Tauri | 前端可复用；原生能力和构建涉及 Rust 工具链 | Windows WebView2、权限范围、插件与打包环境 |

不在本阶段固定选型。确定安装包体积要求、Windows 最低版本、自动更新方式和团队工具链后再选择。具体版本、打包配置和平台要求在实际实施时以相应官方文档为准。

## 3. 平台适配点

目前 `src/platform/browser.ts` 提供 copyText 和 downloadText。桌面接入时保留相同上层调用语义：

- 复制：调用容器受限剪贴板接口。
- 保存：原生保存对话框，返回成功/取消/失败；不能把“用户取消”报错。
- 导入：目前 file input 本身可在很多 WebView 工作；如改为原生对话框，抽出 readTextFile，并继续执行 UTF-8 与容量检查。
- 不要在 JSON core 中引入 Node fs 或 Rust 调用。

选择桌面容器后再建立浏览器/桌面双适配器。现在不放无用的 IPC 占位代码。

## 4. 打包阶段必须完成的内容

1. Windows 应用标识、图标、名称、版本、安装路径和卸载行为。
2. 构建产物内置全部依赖，确认断网冷启动可用。
3. 验证 Worker、编辑器、中文字体、缩放、复制、导入、保存。
4. 验证未知 Hash 路径、刷新、菜单切换和关闭窗口。
5. 限制原生权限，不允许输入内容触发任意命令或外部 URL。
6. 决定是否签名、分发方式和自动更新；自动更新属于独立联网能力。
7. 如需最近文件或历史记录，先单独设计用户开关和敏感数据存储方案。

## 5. 桌面验收矩阵

Windows 11、不同 DPI（100/125/150%）、中文路径、长路径、保存取消、无文件权限、剪贴板失败、断网首次运行、1 MiB 边界、超时终止、窗口缩放、系统休眠恢复。

当前代码未执行这些原生桌面测试。网页构建通过不等于桌面安装包已验证。

## 6. 编码工具增量

URL、Base64、Unicode、HTML Entity 的 core.ts 与编码 Worker 可直接复用到桌面容器；HTML 实体表随包离线提供。下载接口已支持 text/plain MIME。桌面验收需新增中文/emoji、CRLF/BOM 文件往返、Base64 非法输入及 HTML 结果不执行等用例。当前仍未生成原生安装包。

## 7. 新增安全、时间与 SQL 工具

JWT、哈希、HMAC、SQL 继续复用纯函数与 Worker；无需 Node 密码学权限或数据库连接。桌面容器必须支持模块 Worker 及其动态导入。时间戳依赖系统 Intl 时区数据，应验证 WebView2 的 IANA 时区和夏令时行为。HMAC 密钥不进入桌面持久化配置；是否需要系统凭据保险库应另立需求。当前未生成或验证原生安装包。
