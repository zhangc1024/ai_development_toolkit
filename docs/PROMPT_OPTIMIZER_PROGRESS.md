# 提示词优化：分步实现与续接记录

## 协作方式
- 最初每轮一小步；用户后续明确要求“把剩下来的全部实现”，本轮据此完成剩余步骤。
- 每次开始前先更新本文档的“本轮范围”，完成后记录验证结果和下一步。
- 新会话先读本文档，再读相关源码；不要一次实现剩余所有步骤。
- 保留项目已有未提交修改，不重构、不清理其他工具。

## 已确定的需求
- 沿用 Vue 3 + TypeScript 和原有淡紫色工具箱界面，Hash 路由为 #/prompt。
- 保持纯静态；默认静态规则可用，Ollama 为可选增强。
- Ollama 支持本机、局域网 IP、内网域名和团队内网服务器，不限制 localhost。
- 不接入在线 AI 平台，不增加账号、后端、数据库、API Key 管理。
- 不默认保存输入或生成结果；仅保存配置。
- 自动模式：未启用 Ollama 直接静态；启用后失败可明确提示并降级。
- 手动 Ollama：失败显示错误，不暗中降级；主动取消也不触发降级。
- 分类支持自动识别与手动选择；原始需求完整保留，不虚构缺失信息。
- 模型列表未来从服务读取；本机/内网部署不等于模型一定离线，接入时再检查模型能力和云端边界。
- CORS、浏览器本地网络权限与服务器开放配置需在连接阶段说明，不自动修改服务器。

## 步骤 2 手工验收
1. 打开 #/prompt，选择静态规则，输入需求后生成；检查原文与选中的维度。
2. 全部取消维度再次生成，结果应与原文一致；空白输入报错，已有结果保留。
3. 编辑结果后复制并粘贴，确认复制的是编辑后内容；拒绝剪贴板权限时显示提示。
4. 修改输入或选项，检查旧结果提示；再次生成覆盖旧结果。
5. 开启 Ollama 使用自动模式或手动 Ollama，点击优化应提示尚未接入，无模型请求。
6. 刷新后仅配置恢复，输入和结果均为空。
