# 编码转换工具使用说明

四个页面均已实现，数据仅在浏览器内存与 Web Worker 中处理，不需要 API、账号或后台。

| 页面 | 地址 | 默认模式 |
| --- | --- | --- |
| URL 编解码 | #/url | URL 参数 / 组件 |
| Base64 编解码 | #/base64 | 标准 Base64 |
| Unicode 编解码 | #/unicode | 非 ASCII + 控制字符 |
| HTML Entity 编解码 | #/html-entity | 仅特殊字符 |

## 一、共用操作与数据生命周期

| 操作 | 具体行为 |
| --- | --- |
| 编码 / 解码 | 根据当前模式处理左侧文本，结果显示在右侧只读编辑器 |
| 转换模式 | 决定具体编码规则；修改后清空旧结果，需再次执行 |
| 结果作为输入 | 用右侧结果替换左侧，清除右侧与旧状态，不自动执行；适合反向转换或逐层解码 |
| 加载示例 | 替换输入并自动编码，用于理解当前模式 |
| 导入 | 读取本机 UTF-8 .txt/.json 文本；不上传，导入后手动选择操作 |
| 复制 | 复制右侧完整结果；失败提示手动选中后 Ctrl+C |
| 下载 | 保存为 {工具ID}-{encode或decode}.txt，MIME 为 text/plain;charset=utf-8 |
| 清空 | 清空输入、结果、提示并终止运行中的任务 |
| 搜索 | 两侧独立搜索，图标或 Ctrl/⌘+F |
| 自动换行 | 两侧同步改变显示，不改变文本 |
| Ctrl/⌘+Enter | 重复上次选择的编码/解码，首次默认编码 |

- 输入为空时，允许转换为空结果；此时仍可复制或下载空文本。
- 首尾空格不自动 trim。字符数按 UTF-16 单元统计，容量按 UTF-8 字节计算。
- 修改输入或设置立即清空结果，避免误复制旧结果。
- 切换工具会卸载旧页面并终止任务；返回时是新的空白页面。刷新也不保存输入。
- 没有 localStorage/IndexedDB 历史、URL 内容参数、埋点或外部转换接口。
- 文本编辑器不使用 JSON 高亮规则；JSON 页面仍保留原本的高亮与折叠。
- 编码操作可能不是幂等的，例如已有 `&amp;` 再编码会变为 `&amp;amp;`，这是一次新的编码。

### 文件与资源限制

- 输入不超过 1 MiB（1,048,576 UTF-8 字节）。
- 文件先检查字节数，再按 UTF-8 严格解码；无效 UTF-8 提示失败。
- 编码工具导入保留 UTF-8 BOM 作为 U+FEFF 文本字符，与 JSON 工具导入去 BOM 的策略不同。
- 用户继续编辑、清空或切换设置后，尚未完成的旧文件读取不会覆盖新输入。
- Worker 超过 5 秒终止；输入变化、工具切换也会终止。
- 输出可能大于输入，仍可复制下载；超过 1 MiB 时不能使用“结果作为输入”。
- 不保证所有设备处理最大容量都零卡顿；编辑器渲染和文件/Worker 数据复制仍有成本。

## 二、URL Encode / Decode

### 1. URL 参数 / 组件

采用 encodeURIComponent / decodeURIComponent 语义。

| 原文 | 编码 |
| --- | --- |
| a b+c&x=1 | a%20b%2Bc%26x%3D1 |
| 中文 | %E4%B8%AD%E6%96%87 |

适用于单个参数值、路径片段等；斜杠、问号、&、= 等也会编码。空格编码为 %20；解码输入 a+b 仍是 a+b。

与 PHP urlencode 不完全相同：后者通常使用表单规则，空格为 +。

### 2. 完整 URL

采用 encodeURI / decodeURI 语义，保留 URL 的 : / ? # & = 等分隔符。

输入 https://example.com/中文?q=a b，编码后仍保持链接结构，只转换中文、空格等字符。

完整 URL 解码会保留已转义的保留字符，例如 %2F 仍为 %2F，不把编码后的斜杠擅自变为路径分隔符。需要完全还原这些字符时，选择“URL 参数 / 组件”。

本工具不判断链接可访问性、不自动补协议、不发起远程请求。

### 3. 表单单个值

遵循 application/x-www-form-urlencoded 单值规则：

- 空格 → +。
- 原始 + → %2B。
- 字母、数字、*、-、.、_ 保留，其他字符按 UTF-8 百分号编码。
- 解码先把 + 转空格，再还原百分号字节。

示例：a b+c → a+b%2Bc → a b+c。

这不是 Query 参数编辑器。直接对 a=1&b=2 编码会把 = 和 & 当作值中的字符编码。Query 拆解/编辑仍为后续规划。

### 4. 错误与层级

残缺的 %、%2、%GG，以及 %FF、截断 UTF-8 等报错，输出清空。孤立 Unicode 代理项也被拒绝。

每次解码一层：%2520 → %20；再次把结果作为输入并解码才得到空格。不会自动重复解码。

参考：[encodeURI](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/encodeURI)、[encodeURIComponent](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/encodeURIComponent)。

## 三、Base64 Encode / Decode

### 1. 编码

将文本转换为 UTF-8 字节，再编码；支持中文与 emoji。

- 标准 Base64：使用 + /，按需带末尾 =。
- Base64URL：使用 - _，编码时省略末尾 =。
- 不对文本自动去空白；换行和 BOM 都属于原文。
- 空文本得到空结果。
- 不是加密工具，不提供密码、密钥或内容保密功能。

示例：中文 → 5Lit5paH；foo → Zm9v；😀? 的 Base64URL 为 8J-YgD8。

### 2. 解码与严格检查

两种模式都接受正确填充和省略填充，但不能混用字母表。

- Zg== 与 Zg 都得到 f。
- Zg=、多余 =、中间的 =、长度余数为 1 都报错。
- 检查未使用的填充位，例如 Zh== 不作为 Zg== 的别名接受。
- 默认拒绝空白；勾选“解码时忽略空格与换行”后，只忽略空格、Tab、CR、LF。
- 非断行空格等其他 Unicode 空白仍拒绝，不静默修改输入。
- 字节必须是有效 UTF-8；/w== 虽可表示字节，但不是合法 UTF-8 文本，因此报错。
- Data URL 前缀不自动剥离，图片/压缩包等二进制输出不在范围内。

### 3. 常见误区

JWT 片段通常使用 Base64URL，应选择对应模式；不等同于 JWT 完整解析或验签。

Base64URL 可能包含 - _，放进标准模式会报错。纯字母数字的内容可能同时符合两种字母表，这是正常情况。

## 四、Unicode Encode / Decode

### 1. 两种编码范围

- “非 ASCII + 控制字符”：非 ASCII、ASCII 控制字符、反斜杠转换为 \uXXXX，可读 ASCII 保留。
- “全部字符”：每一个 UTF-16 单元都转换为 \uXXXX。

示例：

~~~text
输入：A中😀
非 ASCII：A\u4e2d\ud83d\ude00
全部字符：\u0041\u4e2d\ud83d\ude00
~~~

emoji 输出两个 UTF-16 代理项，而不是错误的单个四位数。反斜杠编码为 \u005c，避免原文中形似转义的文本在往返时被意外解码。换行编码为 \u000a。

### 2. 解码语法

同时支持：

- \u4e2d → 中。
- \ud83d\ude00 → 😀。
- \u{1F600} → 😀。

编码范围选项不影响解码。不移除外层引号，只还原 Unicode 转义。普通 \n、\t、\x41 等保持原样，不把整个输入当作 JavaScript 或 JSON 执行。

连续两个反斜杠按原文保留，不从第二个反斜杠再次匹配。例如两个反斜杠紧接 u4e2d 不会变成“中”。

每次一层：\u005cu4e2d → 字面文本 \u4e2d，第二次解码才变成“中”。

### 3. 错误

拒绝 \u、\u123、非十六进制、缺少右花括号、码点大于 10FFFF、码点写法落在代理区、未配对高/低代理项。

转义错误位置从 1 开始按 UTF-16 单元计算；未配对代理项提示原因但不假报具体行列。这不是字符集转换工具，不支持 GBK/UTF-16 文件解码。

## 五、HTML Entity Encode / Decode

### 1. 编码模式

“仅特殊字符”编码五类字符：

| 原字符 | 结果 |
| --- | --- |
| & | `&amp;` |
| < | `&lt;` |
| > | `&gt;` |
| 双引号 | `&quot;` |
| 单引号 | `&#39;` |

“特殊字符 + 非 ASCII”在此基础上，把非 ASCII 码点转成十六进制数字实体，例如 中 → `&#x4E2D;`，😀 → `&#x1F600;`。

不将整个 HTML 源码解析成 DOM，不做标签格式化。

### 2. 解码规则

使用随项目打包的 entities 库。支持 HTML 命名实体（如 `&copy;`、`&nbsp;`）、十进制和十六进制数字实体；仅解码带分号的实体。

- `&copy;` → ©。
- `&#20013;` → 中。
- `&#x1F600;` → 😀。
- `&unknown;` 保留原样。
- &amp（无分号）保留原样。
- `&amp;lt;` 单次得到 `&lt;`，不继续解成 <。

这里的“带分号解码”不等于验证输入完全合法。非法数字码点按 HTML 规则处理，例如零、代理项、超出 Unicode 范围的数值替换为 U+FFFD；部分历史控制码也可能按 HTML 兼容规则映射。

参考：[entities 官方说明](https://github.com/fb55/entities)。

### 3. 展示边界

所有结果进入纯文本编辑器，即使解码后包含 script、img、事件属性，也不作为 HTML 插入页面，不请求其中资源。

输出不是 HTML 安全清洗结果，也不能直接当作“安全 HTML”放入其他应用的 innerHTML。

## 六、验收与实现入口

核心测试：tests/encoding.test.ts；覆盖标准向量、往返、Unicode 边界、空文本、填充、实体保留行为与容量限制。

实现文件：

- src/tools/encoding/core.ts：纯转换逻辑，无 DOM/网络。
- src/tools/encoding/config.ts：四个工具的模式、示例与界面说明。
- src/tools/encoding/encoding.worker.ts：本地 Worker 入口。
- src/tools/encoding/EncodingTool.vue：统一的输入、操作、输出和状态。
- src/tools/registry.ts：页面注册、kind 参数、独立地址。
- src/platform/browser.ts：复制和下载；新增 MIME 参数，JSON 下载默认仍为 application/json。

核心算法与 Vue 解耦，后续 Windows 容器可复用；仅系统文件/剪贴板接口按需替换。目前不包含桌面安装包。
