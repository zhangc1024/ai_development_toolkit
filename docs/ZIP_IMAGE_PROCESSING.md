# ZIP 图片批量处理

入口仍为“图片工具 → 图片压缩 / 格式转换”（`#/image-compress`）。
选择或拖入 ZIP 后自动扫描清单；使用同一组压缩档位和目标格式，点击“开始处理 ZIP”，完成后下载“原包名-processed.zip”。
只读取本地文件，不上传；RAR、加密包、分卷包、自解压包暂不支持。

## 处理规则
- ZIP 内目录逐级保留，包括空目录。可编码原格式压缩保留文件原名，不添加单图下载后缀；HEIC/RAW 的原格式选项转换为 PNG，更改扩展名并避让冲突。
- 识别并处理静态 PNG/JPG/WebP/HEIC/HEIF/AVIF/TIFF/BMP 和支持的相机 RAW，依据文件头与解码器验证；扩展名缺失或不符但文件头可识别的图片也会处理。
- GIF、APNG、动态 WebP、SVG 等不支持图片原样保留，清单说明原因。
- 图片损坏、尺寸超限、编码失败或单图超时：保留原字节与原路径，继续后续文件。
- 非图片、内部 ZIP/RAR 原样保留，不递归解包，不执行任何包内文件。
- 明确选择目标格式时更改扩展名。同名或大小写冲突时添加 -2、-3 等序号，保留原有文件与文件夹，禁止覆盖。
- 输出目录和原有路径均提前保留，避免覆盖尚未处理的条目；同格式显式转换不强行改写原文件名大小写。
- HTML/CSS/JSON 等文件里的图片路径引用不修改。使用转换格式时，用户需自行更新这些引用。
- 解压失败、CRC 校验失败、包结构损坏、总量超限或打包失败：终止整个任务，不提供部分结果 ZIP。
- 不支持不安全路径、符号链接/特殊文件、重复路径、大小写/NFC 归一化冲突和文件/目录冲突。普通 Windows 反斜杠路径规范化为 /。
- 重新打包保留普通文件内容与目录结构，尽量保留文件修改时间；不承诺保留原 ZIP 的所有权限、注释、扩展字段或签名信息。
- 中文文件名按 ZIP UTF-8/Unicode 字段读取。老式非标准编码 ZIP 未做人工编码切换，遇到乱码应先用本地解压软件重新打包为 UTF-8 ZIP。

## 容量和任务限制
| 项目 | 限制 |
| --- | --- |
| 输入 ZIP | 50 MiB |
| 条目数 | 500，包含文件和显式文件夹 |
| 解压文件总量 | 200 MiB，扫描检查声明值，解压时再累计实际输出 |
| 转换后文件总量 | 200 MiB |
| 最终 ZIP | 2100 MiB，包含目录及归档开销 |
| 单图 | 100 MiB、6400 万像素、单边 16384 |
| 单图处理 | 60 秒，超时保留原图并继续 |
| 扫描/解压/打包阶段 | 无阶段更新超过 120 秒则终止整包 |

串行读取条目、处理图片和写入 ZIP，最多同时存在一个图片编码任务。
输出 ZIP 仍在浏览器内存生成，内存占用会高于输入包大小；不承诺移动设备可稳定处理上限大小。这里不是面向 GB 级压缩包的流式落盘工具。
不保留历史或密码。取消、修改选项、替换文件、清空、离开页面均终止相应 Worker 并释放结果 URL。
取消扫描后可重新扫描；取消处理后可重新开始。扫描清单不代表内容完整性已验证，CRC 在逐条解压时检查。

## 结果展示
- 当前阶段与路径、已完成/总条目进度。
- 文件路径、原始大小、处理状态/原因、输出路径/大小。
- 已处理、原样保留、失败并保留数量（不含目录）。
- 图片原始总大小与结果总大小；失败及不支持图片按原体积计入。
- 输入 ZIP 和结果 ZIP 的体积变化。ZIP 容器变化不等于图片压缩率。
- 批量模式不同时渲染每张图预览，以控制内存。单图对比功能保持独立。

## 实现
- `zip-policy.ts`：限额、路径检查、重名分配、图片识别与错误翻译。
- `zip-engine.ts`：扫描、受限解压、CRC 校验、逐条处理、打包；图片处理通过回调注入，便于独立测试。
- `zip.worker.ts`：ZIP Worker，与页面交换当前图片任务。
- `ZipImageTool.vue`：清单、进度、结果、ZIP/图片 Worker 生命周期。
- 图片压缩复用 `compress.worker.ts`；失败不会改变原始字节。
- 依赖 @zip.js/zip.js 2.15.0，BSD-3-Clause；许可证存放于 `public/licenses/zipjs-BSD-3-Clause.txt`。
- ZIP 库在独立 Worker 内运行，关闭它自身的 Worker 池，确保取消时无遗留后台线程。不增加后端接口。
- 图片条目以 ZIP STORE 写出，其他文件使用 Deflate；避免反复压缩已编码图片。
