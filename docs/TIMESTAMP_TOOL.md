# 时间戳转换（#/timestamp）

## 1. 功能

双向转换 Unix 秒/毫秒和日期时间，支持 IANA 时区、毫秒精度、负时间戳、当前设备时间及逐项复制。

本工具不联网，不校准服务器时间，不提供时间差计算（仍为后续规划）。

## 2. 输入

### 时间戳 → 日期

显式选择输入单位，不按位数猜测：

- 秒：整数或最多三位小数，例如 0、1767225600、-0.001。
- 毫秒：整数，例如 1767225600000、-1。
- 允许前导负号和首尾空白；不接受正号、科学计数法、NaN、Infinity、数字分隔符。
- 秒字符串先以 BigInt 解析成毫秒，避免 1.001 × 1000 的浮点截断错误。

支持公元 0001–9999 年，UTC 和所选时区两种表示都必须落在范围内。

### 日期 → 时间戳

格式：

~~~text
YYYY-MM-DD HH:mm:ss
YYYY-MM-DD HH:mm:ss.SSS
YYYY-MM-DDTHH:mm:ss.SSSZ
YYYY-MM-DD HH:mm:ss+08:00
~~~

小数秒可一至三位，会按毫秒解释。日期和时间可由空格或 T 分隔，必须包含时分秒。

没有偏移时，按所选时区解释。带 Z 或 ±HH:mm 时，偏移决定实际瞬间，所选时区仅决定结果显示。

拒绝不存在的日期、24:00、闰秒、过长或不匹配的格式。不会把 2 月 30 日自动滚动到下个月。

## 3. 时区与夏令时

默认采用浏览器所在时区，可选择或输入 IANA 时区，如 UTC、Asia/Shanghai、Asia/Tokyo、America/New_York、Europe/London。

时区规则由运行环境的 Intl 数据提供，Luxon 负责转换。无效/不支持的时区会报错。

- 夏令时春季跳时：不存在的当地时间直接报错。
- 秋季回拨：同一个当地时间可能有两个偏移，要求用户在输入末尾明确添加偏移。
- 例如纽约 2026-11-01 01:30:00 有歧义；添加 -04:00 或 -05:00 后可分别转换，相差一小时。

显式偏移不是“这个时区一定采用该偏移”的断言；它是用户指定的瞬间，结果再换算到所选时区。

## 4. 输出

一次转换显示：

1. Unix 秒，保留必要的毫秒小数。
2. Unix 毫秒整数。
3. UTC ISO 时间。
4. 所选时区的 yyyy-MM-dd HH:mm:ss.SSS。
5. 时区名称。
6. UTC 偏移。

支持逐项复制和复制全部；剪贴板失败有提示。UTC 秒/毫秒不因所选时区变化而改变。

示例：

| 输入 | 模式 | 时区 | 结果 |
| --- | --- | --- | --- |
| 0 | 秒 | Asia/Shanghai | 1970-01-01 08:00:00.000 |
| -0.001 | 秒 | UTC | 1969-12-31 23:59:59.999，毫秒 -1 |
| 1970-01-01 08:00:00 | 日期 | Asia/Shanghai | 秒 0、毫秒 0 |

## 5. 当前时间和操作

- 顶部每秒刷新设备时间、时区与毫秒时间戳。
- “填入当前时间”按当前方向填入并转换；日期模式附带偏移，避免回拨时段歧义。
- “加载示例”按当前方向填入固定示例并转换。
- “清空”清除输入、结果和提示，保留选项。
- Ctrl/⌘+Enter 执行转换。
- 修改输入、单位、方向或时区清除旧结果。
- 当前时钟持续更新，但已生成的转换结果保持快照。
- 切换页面时停止时钟计时器，不存储历史。

不自动推断用户所在城市；默认时区来自浏览器设置。设备时间、系统时区数据库可能不准确。

## 6. 实现与验证

src/tools/timestamp/core.ts 为纯逻辑，TimestampTool.vue 提供界面和设备时钟。日期转换量小，在主线程执行；不需要 Worker 或后端。

tests/workbench.test.ts 覆盖 Unix 0、负毫秒、秒的小数精度、时区、显式偏移、闰年、非法日期和夏令时缺口/重复。

参考：[Luxon API](https://moment.github.io/luxon/api-docs/index.html)。原生 Windows 打包后仍需验证目标 WebView 的时区支持。
