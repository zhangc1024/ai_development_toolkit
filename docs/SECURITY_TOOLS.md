# JWT、哈希与 HMAC 工具

这三个工具全部在浏览器本地计算。JWT 解析、摘要和签名在独立 Worker 内运行；不提交输入、不保存历史、不调用外部验证服务。

## 1. 公共操作

| 操作 | 行为 |
| --- | --- |
| 主操作 | 根据当前工具解析 JWT、计算哈希或计算 HMAC |
| 加载示例 | 替换消息并运行；HMAC 同时把密钥设为 key，密钥/消息编码恢复 UTF-8 |
| 导入 | 读取 UTF-8 文本文件，最多 1 MiB；BOM、CRLF 和空白保留；不是任意二进制文件上传 |
| 清空 | 清除消息、结果和密钥；隐藏密钥，终止任务 |
| 搜索 | 两侧编辑器独立搜索，Ctrl/⌘+F |
| Ctrl/⌘+Enter | 执行当前工具主操作 |
| 复制 | 复制完整结果；权限失败时提示手动选择复制 |
| 下载 | jwt-result.txt、hash-result.txt、hmac-result.txt；UTF-8 text/plain |
| 自动换行 | 只改变编辑器显示，不修改消息字节 |

- 输入和设置变化会终止旧任务、清除旧输出。
- 切换工具和刷新不恢复内容；HMAC 密钥不放进 URL、导出文件或本地存储。
- 输入上限为 1 MiB UTF-8 字节；HMAC 密钥输入文本另限 64 KiB。Hex/Base64 在解码前按输入文本计算限额。
- Worker 超过 5 秒终止；动态模块首次加载时间也包含在计时中。
- 空消息允许计算哈希/HMAC；JWT 空输入报错。
- 字符统计按 UTF-16 单元计数，容量按 UTF-8 字节。

## 2. JWT 解析（#/jwt）

### 支持的输入

支持三段紧凑格式 Header.Payload.Signature。允许首尾空白和 Bearer 前缀（大小写不敏感）；不删除 Token 内部空白。

Header/Payload 必须是无填充 Base64URL 编码的 UTF-8 JSON 对象。拒绝数组、标量、注释、尾逗号及重复顶层字段；转义后相同的字段名也算重复。

每段按标准 Base64URL 字母表检查，拒绝错误长度和非规范填充位。五段 JWE、b64=false 载荷不支持。

### 结果

结果编辑器按 Header、Payload、Signature 分区展示，签名保留 Base64URL 原文。格式化 JSON 时保留大整数和原始数值表示，不将内容重新序列化为可能丢精度的对象，也不生成新的 Token。

Header.alg 必须是非空字符串；它只是 Token 自己的声明，不能据此确认实际算法或签名正确。

- 非 none 算法要求非空签名段，但不按算法检查签名长度，也不做密码学验证。
- alg=none 允许空签名，醒目标注没有签名；none 搭配非空签名视为格式错误。
- 包含 crit 时提示不验证扩展语义。
- 示例明确使用 alg=none；它是调试数据，不是可用于认证的凭证。

### 时间声明

读取 Payload 的 iat（签发）、nbf（不早于）、exp（到期）：

1. 只接受有限的 NumericDate 数字，单位固定为秒；不把数字字符串或看似毫秒的值自动转换。
2. 显示原始值、UTC ISO 时间和提示。
3. exp <= 解析时设备时间：提示已过期。
4. nbf > 解析时设备时间：提示尚未生效。
5. iat 在未来：提示签发时间位于设备时间之后。
6. 缺少 exp：提示无法判断是否到期。
7. 类型错误或超出 Date 可表示范围：保留原文并提示无法转换。

判断基于点击解析时的设备时间快照，结果不会倒计时自动刷新；需要重新解析才能更新。日期显示精度为毫秒，JSON 原数值原文保留。没有时钟偏差宽限，不联网校准。

### 信任边界

界面始终显示“未验签”。不会因为解析成功、尚未到期或算法名看起来正确而宣布 Token 有效。

不校验签名、公钥、iss、aud、权限、吊销状态、业务字段或扩展。不要把工具的解析成功作为登录或鉴权依据。解析结果中的 HTML 一律按文本显示。

参考：[RFC 7519](https://www.rfc-editor.org/rfc/rfc7519)。

## 3. MD5 / SHA 哈希（#/hash）

### 算法

MD5、SHA-1、SHA-256（默认）、SHA-512。每次计算所选的一种算法。

| 算法 | 原始摘要长度 | Hex 字符数 |
| --- | --- | --- |
| MD5 | 16 字节 | 32 |
| SHA-1 | 20 字节 | 40 |
| SHA-256 | 32 字节 | 64 |
| SHA-512 | 64 字节 | 128 |

### 输入编码

- UTF-8：按文本编码为字节；中文和 emoji 支持，未配对代理项报错。
- Hex：两位代表一个字节；允许大小写，不允许 0x、奇数位、空格或冒号。
- Base64：按标准字母表还原任意字节；可包含不是有效 UTF-8 的字节。与“Base64 文本解码工具”不同，不要求解码结果是文本。
- Base64 允许正确填充或省略填充；拒绝空白、Base64URL 字母、错误填充和非规范尾部填充位。

不会 trim、转义或规范化文本。abc、abc 加换行、前后加空格的摘要不同。

### 输出编码

小写 Hex、大写 Hex、标准 Base64。Base64 编码的是原始摘要字节，不是 Hex 文本。

已知示例：UTF-8 abc 的 MD5 为 900150983cd24fb0d6963f7d28e17f72。

空字符串也有定义明确的摘要。本版不做文件二进制摘要、批量算法对照或摘要反查。

MD5/SHA-1 仅供旧系统兼容，不应作为新的抗碰撞安全方案。通用摘要不能代替密码哈希方案；工具不会加密或保护输入内容。

## 4. HMAC 签名（#/hmac）

### 输入与算法

默认 HMAC-SHA-256，也提供 HMAC-MD5、HMAC-SHA-1、HMAC-SHA-512 供兼容调试。

消息和密钥分别选择 UTF-8、Hex、Base64。两者必须按照服务端协议选择字节解释：

- UTF-8 密钥 ff 是两个字符。
- Hex 密钥 ff 是单字节 0xff。
- Base64 密钥 /w== 同样是单字节 0xff。

密钥不是先哈希后使用，也不自动拼到消息前后。计算使用标准 HMAC 算法，长密钥处理交给实现库。

### 密钥界面与空密钥

默认隐藏密钥，可主动显示。默认拒绝空密钥；只有勾选“允许空密钥（测试）”才允许。空消息可以正常签名。

“加载示例”会覆盖消息和密钥，使用公开的 key 和示例消息；不要把示例密钥当作业务密钥。

清空、切换工具或刷新会清除页面状态。计算后的临时密钥字节数组会置零，但 JavaScript 字符串、浏览器内存副本无法保证物理擦除，因此不宣称内存安全销毁。

### 输出与示例

输出是原始 MAC 字节的 Hex 或 Base64，没有参数排序、URL 编码、JSON 序列化、时间戳拼接等额外处理。

示例消息 The quick brown fox jumps over the lazy dog、密钥 key，均 UTF-8，HMAC-SHA-256 Hex：

~~~text
f7bc83f430538424b13298e6aa6fb143ef4d59a14946175997479dbc2d1a3cd8
~~~

这不是 JWT 签发器，也不直接实现微信/支付宝/其他平台专有签名协议。

## 5. 实现与验证

- src/tools/security/bytes.ts：严格字节输入、Base64、输出编码和限制。
- src/tools/security/crypto.ts：@noble/hashes 的摘要与 HMAC。
- src/tools/security/jwt.ts：JWT 分段、JSON 展示、时间声明。
- src/tools/workbench/：共用工作区、Worker 和规则配置。
- tests/workbench.test.ts：已知向量，与 Node crypto 对照，错误输入和 JWT 边界。

所有运行依赖随静态产物发布。Node crypto 仅用于测试对照，网页中不使用 Node API。参考：[noble-hashes](https://github.com/paulmillr/noble-hashes)。
