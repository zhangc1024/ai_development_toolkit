# Windows 桌面版后续验收（2026-11-02）

本次继续补齐 WINDOWS_DESKTOP_RELEASE.md 的剩余项。应用运行代码和 0.1.0 安装包未修改；新增/修正的是验收脚本及一个测试兼容性修复。

## 已完成

- 文本复制按钮、图片复制按钮、Ctrl+C/Ctrl+V 均实际经过 Windows 系统剪贴板，并用独立 WinForms 程序回读确认。Chrome 键盘事件触发系统复制/粘贴，不是构造 ClipboardEvent 来假定通过。
- 纠正旧剪贴板结论：旧测试在复制仍未结束时写入了另一个探针字符串，并过早匹配“可复制图片”的生成提示，造成并发覆盖/过早读取。串行等待“已复制”后，文本和 320×200 图片均通过。不能将旧测试结果继续归因为系统剪贴板不可用。
- 修复 Windows Node 24 的测试 harness：Vue CJS 命名空间含非合法形参名 module.exports，生成 new Function 时需过滤这类标记。不改聊天业务代码。Windows 与 WSL 现在均为 36 文件、746 项测试通过。
- 连续 100 次同名覆盖保存：每次磁盘内容与输入字节相同，全部会话完成、没有临时文件；共约 6.75 秒。工作集采样从 553552 到 565872 KiB，该短测试只验证保存链路反复执行。

## 内存对照与复测

第一轮十分钟完成 370 轮、约 2960 次工具切换，无页面错误；工作集和旧 DOM 节点增长。没有直接把该现象标成“无泄漏”。

对照结果：

- 纯导航后，GC 可回到约 557 节点、122 个监听器。
- 相同的 60 次图片处理，Playwright setInputFiles 方式在 GC 后保留 14628 节点、1891 个监听器。
- 改用页面 File/change 事件注入相同图片，经相同处理和 GC 后为 167 节点、64 个监听器；清理控制台不会改变这些结果。

这组对照表明旧节点保留与自动化文件选择方式相关；它不是纯导航或相同图片计算流程中的组件卸载泄漏证据。为避免将调试持有误报为产品泄漏，第二轮十分钟循环改用页面 File/change 输入；这用于压力计算，不替代原生文件选择器验收。首轮的真实文件导入/落盘与大图/大 ZIP 检查仍有效。

第二轮完成 603219ms、388 轮、约 3104 次工具切换；每轮对压缩/照片边框/文字水印/九宫格/Base64 执行输入或生成，另外三个工具切换打开。无页面错误。压力计算输入用页面 File/change 事件；实际文件导入及另存为文件系统链路由之前的端到端测试、上限样本及连续 100 次保存另行覆盖。

第二轮观察工作集峰值 703212 KiB（约 687 MiB），最终 634148 KiB（约 619 MiB）；中后段采样有波动，没有第一轮那样的旧组件累积。完整观察期后才执行诊断 GC：

| 指标 | 回收前 | 回收后 |
| --- | --- | --- |
| DOM 节点 | 1312 | 244 |
| 事件监听器 | 224 | 61 |
| JS 堆使用量 | 7,391,908 字节 | 5,741,492 字节 |

回收后的节点 <5000、监听器 <1000 回归门槛已通过，并加入测试脚本。没有通过改变应用代码、提高上限或在十分钟观察期间反复强制 GC 来压低指标。这证明当前代表性十分钟流程未见组件对象持续滞留；不将它外推为所有机器、所有素材、任意时长的保证。

## 环境与未关闭项

- 原生 UI 控制的 node_repl 与 CUA 入口仍因 CreateProcessSecurityEnvironment failed (0x80070001) 无法启动。没有改系统安全配置或用自制 UI 自动化绕过它。
- 实测只有一个显示器，1920×1080，系统比例 100%。没有其他物理 DPI/第二显示器的验收证据。
- WindowsSandbox.exe 不存在，当前机器仍有 Node/WSL；干净机器验收不能靠清空 PATH 冒充。
- 用户已答复将人工检查“选择目录保存、取消、重名覆盖”，目前等待实际结果。仅将明确反馈的项目记录为“用户人工验收”，见 WINDOWS_DESKTOP_MANUAL_QA.md。
- 本轮仍为用户批准的未签名内部版；正式发布者、公开签名及公开分发准备不在本轮交付范围。

证据：Windows checkout 的 output/desktop-followup、output/desktop-stress。所有压力样本、测试配置和日志被 Git 忽略，不进入安装包。
